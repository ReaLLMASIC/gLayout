# E1 controlled action interfaces

Status: prospective protocol, not yet frozen. The freeze records the actual task, library, evaluator, model, analysis and source bytes before formal dispatch. This E1 freeze is separate from the remaining E2–E5 work and does not turn development pilots into formal trials.

The fixed design is 24 sized task families × G0/G1/G2 × five fresh trials = 360 episodes. Eight target logics each contribute three role rotations of the same declared 25-point domain. Each trial sees one anchor and eight development configurations; sixteen are withheld. The shared-domain relationship remains explicit. There are eight primary source groups and seven groups in the sensitivity analysis merging cascode mirror and source follower. These are not 24 independent circuits. Twelve tasks allow reuse and twelve require composition; report the strata separately.

G0 receives generic geometry APIs and complete effective PDK rules and device definitions. G1 additionally receives actual MOS/MIM PCells and their real terminal metadata. G2 additionally receives cropped common generator/routing interfaces. A complete target block is available only in the declared G2 reuse stratum. Composition source packs contain no target assembly. A backend constructs each read-only primitive library from the independent reference for the current configuration, including previously unseen dimensions. An anchor-only PCell library does not satisfy this interface.

Every episode uses a fresh isolated GPT session under the same saved model configuration. The common Qwen tokenizer revision is `381fc969f78efac66bc87ff7ddeadb7e73c218a7`. The full current editable source, core contract, effective PDK rules and actual access metadata must fit an 8192-token context including a 1024-token output reserve. Overlong inputs are rejected before inference; overlong returned actions retain raw output and observed usage but are not applied. `current_source_and_feedback_v1` supplies the complete current source and every physical feedback/error/action summary. Superseded historical source and patch payloads remain in raw logs. Native filesystem, shell, external retrieval and delegation are unavailable to the tested policy.

The search limit is 1200 seconds of absolute UTC time, ten decisions and three physical point calls. Every requested configuration counts once, including generation failures and basic checks. Each episode has one physical worker with two CPU cores. The candidate and trusted evaluator stages share the same remaining episode time; a new stage cannot start after the deadline. Cleanup and every actual resource cost remain recorded. Patches, source reads and requests use the same action schema across methods. Fresh trial numbers are identifiers, not claims of controllable GPT sampling seeds.

The common feedback includes actual checks and measured corner metrics. Failures additionally expose bounded diagnostic samples: the last twelve generation diagnostic lines (at most 2000 characters), the first four DRC rule groups with two coordinate boxes each, and the last twelve LVS report lines (at most 1600 characters), plus available exact device-intent differences. Counts and omitted material are explicit, and the complete reports remain in raw evidence. These are samples of the real logs; they do not change failure classification or provide an engineer-written repair. The same diagnostic interface applies to G0/G1/G2.

S0 requires an emitted, accepted GDS. S1 requires the named target's full recursive area to pass completed full-rule DRC, independent unique LVS and the per-finger device/terminal graph check. The independent reference fixes models, dimensions, multiplicity, ports and connectivity. S2 requires S1, positive unsimplified extracted R/C and every applicable declared analysis and electrical specification at tt/ss/ff, 1.8V and 27°C. Loads and biases are task-specific and frozen. Basic correctness requests do not establish S2. Numerical incompleteness or an infrastructure failure is distinct from a verified candidate failure.

The primary search endpoint is verified S2 generation within the search budget. Record the first within-budget S0/S1/S2 trusted feedback times, after the complete requested call returns and the host independently inspects its evidence. These are not inferred internal GDS/DRC/LVS completion times; the three tiers may share one feedback timestamp after a full call. A later source edit cannot make an earlier verified layout the final delivered generator: final-source anchor results are separate. After search, seal one source. Complete its nine visible points without further policy feedback, then evaluate the sixteen hidden points once. Keep search, post-freeze diagnostics and hidden acquisition costs separate. Hidden results never return to editing, teacher collection or calibration. A missing or incomplete point remains unresolved rather than becoming a fabricated electrical failure.

Task-feasibility and mechanical interface controls precede freezing. Original layout failures remain task evidence rather than a reason to select only successful layouts. A task with an unestablished reference or intrinsically unachievable electrical contract is not admitted as a model-failure test. Freeze the actual qualification bindings, not only a boolean readiness flag.

The primary contrasts are G1−G0 and G2−G1 within reuse and composition; G2−G0 is explanatory. Compute task-paired differences after the five trials of every method are present. Bootstrap whole source groups with 2000 replicates, seed 20261018, and report percentile 95% intervals plus the seven-group sensitivity. Configuration and inference repetitions do not increase the circuit count. Budgeted success curves and restricted mean time to verified success retain unsuccessful searches at the full budget. Actual cost is reported separately from this time-to-event endpoint. An undispatched or infrastructure-paused episode remains in the fixed matrix as unresolved; incomplete matrices do not produce the primary paired comparison. Full-matrix rate bounds retain all declared rows: observed verifications form the lower bound, while unverified unresolved rows may contribute to the upper bound. These are identification bounds, not confidence intervals or fabricated circuit-failure labels. Conditional completed-search rates are reported separately.

`src/e1_analysis.py` and `scripts/analyze_e1.py` implement these definitions. Formal analysis requires the frozen matrix and a trusted dispatch index; it refuses development episodes, duplicate trial identities and outcomes outside the plan. A real second-framework check on six common tasks remains additional required work. The installed image contains real GF180 and IHP PDK resources, but BAG and laygo2 imports are absent; the environment inventory alone is not a physical comparison.

`scripts/run_e1_suite.py` dispatches the exact 360-episode matrix. It randomizes task/trial blocks with seed 20261018, then randomizes the three methods within each block. Up to four episodes run concurrently, each retaining its original one-worker/two-CPU budget; a new launch requires measured busy CPU plus two to remain at most 24 and RAM use at most 190 GiB. The saved index supports resuming the same plan. An interrupted child with no final report stays unresolved and pauses new dispatch; it is never silently repeated. A pause request drains already running episodes. Scheduling order and queue wait are recorded separately from each episode's search limit.

Completed point evidence is compressed on the trusted endpoint by `scripts/archive_e1_episode.py`. Every ordinary source/evidence file is compared byte for byte against the private tar stream before its uncompressed copy is removed. Task state, sealed source, public summary and an explicit archive/restore index remain. This changes storage only and runs no new simulation. Archiving wall/CPU costs are recorded separately. Hidden raw data and private archives stay on the endpoint. New dispatch pauses below 4 GiB free disk. A completed mirror control measured 4,917,552 raw file bytes to 660,453 archive bytes (13.43%); this is a development capacity measurement rather than an assurance that every OTA has the same ratio.
