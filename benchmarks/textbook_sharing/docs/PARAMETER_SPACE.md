# Parameter space and counts

Generated by `python -m textbook_sharing.analysis.report` from `results/analysis/benchmark_table.json`, `results/count_ledger.json` and `results/analysis/scope_audit.json`; do not edit by hand.

## Three nested levels

1. **Process**: SKY130 (1.8 V devices), GF180MCU (3.3 V), IHP SG13G2 (1.2 V low-voltage devices).
2. **Size**: every transistor width is scaled by sW in {0.5, 1, 1.5, 2} and every length by sL in {1, 1.5, 2}, i.e. 12 size points per topology and process.  Widths are scaled through the finger count when that stays an integer for every device, otherwise through the unit finger width, so every width ratio inside a circuit is kept; a request whose unit finger width falls below the PDK minimum or off the 5 nm grid is parameter-illegal (`textbook_sharing/grid.py`).  Resistor and capacitor values, supply, bias and load are not scaled.
3. **Plan**: for each sharing group, six discrete axes (arrangement 4 values, orientation policy 4, diffusion 2, gate 2, first strap side 2, pad end 2) give 256 tuples; illegal tuples and tuples that build the same geometry as another are removed (`src/glayout/sharing/enumeration.py`).  The plans of a circuit are the product over its groups.  Plans written directly as a `SharingPlan` can express more than these axes.

Requests: 18 topologies x 3 PDKs x 12 sizes = **648**.

* 17 of 18 topologies have formal entries.  Every point of the class-AB stage (C18) misses its schematic floors, also after a bounded redesign search (`results/redesign_search/`).
* 13 topologies admit sharing across devices.  In C04, C12, C15, C17 no two transistors of the same polarity, length and unit width share a source/drain or gate net, so every group holds one transistor and only the unshared layout exists.
* Main grid: every qualified request in the four named modes = 2204 runs: auto_passed 1608, NA 592, spec_failed 4.  NA = the mode shares nothing in any group of that circuit (no run is made); the failures are the unshared references of the table above.
